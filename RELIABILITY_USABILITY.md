# Reliability and usability milestone

Development candidate, based on Flow 1.1.5. This work does not replace an
installed server or authorize a new public release. Engine, media bytes,
streaming defaults and public metadata-cache consent remain unchanged.

## Updates and state

Stable installs follow GitHub's explicitly selected Latest release. Preview
selection compares numeric versions. Automatic downgrades and changed source
identities under an installed version are refused. `-AllowDowngrade` is an
explicit recovery option. Required attestation verification binds the artifact
to this repository, an allowed workflow, its immutable source and ref. Restart
health checks verify `/runtime/status` source identity as well as version.

Updater recovery inventory schema 1 lists exact Flow-owned configuration,
database, ACL and managed certificate names. It never scans a shared directory
by broad suffixes. Unknown files, including files created during the update,
remain outside recovery. Recognized new state is quarantined; captured state
is restored only after every inventory entry and digest validates. Junctions,
symbolic links and multiply linked files are rejected. Private backups may
contain account credentials and keys and must remain owner protected.

## Storage migration

`POST /storage/settings` accepts JSON or form data, including a charset.
`settings` and `viewed` accept only `json` or `bbolt`. Optional `revision` fences
modern clients. Legacy `viewedCount` is ignored; malformed types, unknown keys,
duplicate form values, trailing JSON and payloads without editable values fail.
The body limit is 4 KiB.

Changes serialize with other configuration operations, reject stale revisions
or scheduled intent, acquire a maintenance lease and recheck active work. Both
backend snapshots and preferences are captured before mutation. A private,
versioned `flow-storage-transaction.json` recovery journal is capped at 16 MiB.
Writes and readback must succeed for both backends before publication. Failures
restore both originals. An unfinished rollback keeps its journal and blocks
cached database writes until startup recovery succeeds. Startup refuses to
continue if recovery cannot be completed. Live routing changes with the commit;
watched-position updates cannot continue writing into the retired backend.
WAF/GStreamer retain their existing independent JSON storage.

The previous same-length JSON comparison defect is fixed. Verification also
accepts formatting/key-order differences without rounding distinct large JSON
numbers into equality.

## Search and management traffic

The UI displays each completed source while others continue. Torznab has at
most four workers; Torznab and JacRed share a process-wide four-request budget.
The aggregate search deadline is 30 seconds, including waiting for capacity.
Cancellation propagates to HTTP requests. Query, selected source or configured
source changes invalidate obsolete results. A failed source can be retried
explicitly without discarding successful results.

Legacy search routes still return arrays. `details=true` adds `{items,sources}`
with stable source/index identifiers and safe outcome enums: `ok`, `empty`,
`timeout`, `auth_required`, `unavailable`, `invalid_response`, `cancelled`.
Bodies are bounded at 32 MiB. Matching v1 hexadecimal/base32 or v2 identities
deduplicate results; similar titles or sizes do not. V2-only results generate
`urn:btmh:1220` magnets.

429/503 `Retry-After` values establish a monotonic management cooldown, capped
at five minutes. HTTP-date values use the response's server Date. Polling backs
off; mutation requests are never replayed. Existing observations still expire
during a cooldown. Access denial and integration authentication failures have
separate, actionable messages.

## Diagnostics and web interface

Freshness is anchored in the server clock domain plus monotonic time since
browser receipt. The browser's wall clock is never compared directly with
server sample timestamps. New responses also report relative buffer sample
age. Dashboard, playback strip and diagnostic drawer share this mechanism;
missing measurement timestamps produce unknown buffer evidence.

Dashboard troubleshooting distinguishes parser/search failures, Lampa preload
and actual streaming. It links to saved integration tests and reuses the
existing manually started server-to-browser transfer check. That check sends
generated bytes only when requested and does not test swarm bandwidth, packet
loss or the phone decoder. Run it on the phone to measure that network path.

`GET /flow/sessions` derives at most 64 anonymous summaries from the existing
four bounded history files, at most 4 MiB total. It reads nothing while history
is disabled and creates no second recorder. Summaries survive restart through
the existing history, contain no names, torrent hashes, URLs, IPs or client
tokens, and appear only after a manual request. They are included in authenticated
support exports. Rotation, corrupt/dropped records and unconfirmed termination
are marked incomplete. Buffer extrema are sampled; recent stall/wait peaks are
not cumulative counts or player rebuffer measurements. All new UI strings are
provided in Bulgarian, English, French, Romanian, Russian, Ukrainian and Chinese.

## Logs and CI

Each distinct server/web sink retains a 10 MiB active file and two archives.
Shared sinks share one lock and rotation owner. Go logs retain redaction and
control-character escaping. Copy/truncate keeps native descriptors valid;
Windows uses a separate verified non-append handle for truncation. A 250 ms
watcher handles native-only output. Native bursts may briefly exceed the active
threshold and concurrent native writes at the copy/truncate boundary are not
guaranteed lossless. This is bounded diagnostic logging, not an audit ledger.

Mac builds use supported native `macos-15` ARM and `macos-15-intel` Intel pools,
with host/target-specific dependency caches. The historical 1.1.5 recovery stays
as historical evidence. `release-recovery.yml` is the reusable future path:
immutable existing tag, original successful full gates and source-identical
CodeQL, checked binary build metadata, separately attested packaging identity,
and reproducible checksums. Missing Mac assets require explicit owner selection,
a disclosure reason and evidence of unassigned runners. A code failure cannot
be relabeled as a queue failure. Default output is an unpublished candidate;
publishing and Latest are separate explicit inputs. Existing published releases
are not overwritten.

`build/netem_check.py` runs short native TCP jitter, 1% loss and two-second
outage cases inside a disposable Linux network namespace. Every returned Range
is byte checked; recovery timing, memory, descriptor and thread envelopes are
recorded. Host networking and public swarms are excluded. A fixed seed is used
when the hosted iproute2/kernel pair supports it; otherwise the report explicitly
marks seed support false. These are controlled regressions, not Android playback,
real ISP testing or a performance guarantee. No two-hour test is added.
