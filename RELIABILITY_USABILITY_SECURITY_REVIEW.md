# Reliability milestone: security boundaries

Reviewed 24 October 2026. Implementation source and verification receipts are
recorded in [the checklist](RELIABILITY_USABILITY_CHECKLIST.md) and
[PR #9](https://github.com/gnbk21/TorrServer-LT-Flow/pull/9).

## Reviewed changes

- **Administration:** session history, storage settings and integration tests
  use the existing authorized route group and management policy. Authentication
  follows the server's configured HTTP-auth/access rules; an installation with
  authentication disabled still trusts its permitted network clients. The
  storage POST exemption from request counting allows it to acquire its own
  exclusive lease; authentication and management policy still execute first.
- **Storage:** a 4 KiB typed request accepts only the two storage choices and
  an optional configuration revision. Modern drafts retain the revision of
  their matching snapshot. Web and Telegram storage changes share configuration
  serialization and the playback/preparation idle gate. Recovery captures only
  BitTorr settings and Viewed data. Its private, validated journal is limited to
  16 MiB; failed recovery retains the journal and prevents further cached writes.
- **Updates:** exact versioned state names replace shared-directory suffix
  scans. State and backup ancestors, child reparse points and multiply linked
  files are rejected. Backup paths are checked before creation/ACL changes.
  Inventory digests are checked before rollback mutates state. Unknown files,
  media pieces and diagnostic history remain outside rollback. Backups contain
  local secrets and receive restricted permissions before copying.
- **Provenance:** required-attestation mode binds verification to repository,
  workflow, source digest and ref and rejects self-hosted signers. The historical
  recovery workflow remains supported. This policy was also exercised against
  the actual published 1.1.5 executable. New platform recovery requires immutable
  tagged source, source-identical successful security checks and successful full
  validation roles. Queue omissions require explicit selection, disclosure and
  runner-assignment failure evidence. Publishing defaults off; creation refuses
  replacement of an existing release.
- **Indexer traffic:** configured Torznab/JacRed servers can be private LAN
  services. Owner-selected endpoint access remains an administration trust
  boundary. Searches and connection tests now share a four-request budget and
  bounded deadlines; response limits are 32 MiB for searches and 1 MiB for tests.
  Outcomes expose enums; existing URL/credential redaction remains in use.
- **History/support:** summaries derive from the existing opt-in history and
  expose numeric/enum evidence without media names, hashes, URLs, client tokens
  or addresses. Input is at most four 1 MiB files; output contains at most 64
  summaries. Disabled history is not read. Support exports retain their 2 MiB
  bound and exclude raw logs/traces.
- **Logs:** distinct sinks retain an active 10 MiB file and two archives. Shared
  sinks have one rotation owner. Go output retains redaction and control-character
  escaping. Direct native descriptor output has its existing formatting and can
  briefly exceed the threshold between watcher ticks. Copy/truncate preserves
  descriptors but cannot guarantee lossless simultaneous native writes.
- **Network regressions:** netem changes run only after verifying a newly owned
  Linux network namespace. Tests use generated bytes, loopback peers and owned
  processes; they do not alter host interfaces/routes or contact public swarms.

## Existing findings and limits

The repository's existing open CodeQL inventory was rechecked: **30 findings,
23 high and 7 critical**. These include configured/local path and outbound-URL
trust boundaries in existing server, media, certificate and indexer operations.
No finding was dismissed, disabled or relabeled by this milestone. PR analysis
is incremental; its result count must not be presented as the repository's total
or as proof that all existing findings are resolved.

The final [CodeQL run](https://github.com/gnbk21/TorrServer-LT-Flow/actions/runs/40113146676)
completed native Go/C++, Windows guard, JavaScript/TypeScript and Actions analysis
on tested merge `8fa82df77f6a9845b023711a04ac46a14ee0cc21`, reporting zero
incremental findings and no analysis errors or warnings. Native race and reachable
Go vulnerability checks also passed in the implementation verification run.

Automated checks establish the tested behavior and boundaries. Public-swarm
conditions, the owner's Android decoder and physical Windows boot/sleep/network
recovery remain separate field checks. This milestone preserves their previous
disclosures and the owner's installed configuration.
